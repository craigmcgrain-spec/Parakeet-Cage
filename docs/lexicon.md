# The dictionary files: how they are created and maintained

Two files, deliberately kept apart:

| Store | File | Holds | Who writes it |
|---|---|---|---|
| **Your dictionary** | `~/.config/parakeet-cage/lexicon.toml` | only words you added | you (and the *hits* the app counts) |
| **Auto** | `~/.local/share/parakeet-cage/learning/auto.toml` | candidates the app observed, and the ones you accepted | the app, edited through the window |

Both are applied when dictating: your entries first, then Auto's. Nothing is downloaded or sent
anywhere at any point.

## 1. Creation

| When | What happens |
|---|---|
| The daemon starts (`parakeet-cage`) | `lexicon.toml` is created with a commented template, if it does not exist |
| You open the window (`parakeet-cage --dictionary`, or tray → *Dictionary…*) | the same check, so the files appear even if the daemon has never run |
| A fuzzy match is refused | `auto.toml` is created and the candidate written into it |
| `[text] lexicon = false` / `auto_dictionary = false` | that store is skipped entirely and its file is not created |
| An older `learning/pending.toml` exists | its candidates are imported into `auto.toml` on first use |

Paths are XDG-aware, so a sandbox or a different `$HOME` gets its own copies;
`[text] lexicon_path` and `[text] auto_path` override them.

## 2. The life of a word

1. **Notice a mishearing** — the model writes `Castrell` where you said `kestrel`.
2. **Either** add the word yourself (window: *Add word* → word + aliases → *Save*; or edit
   `lexicon.toml` in any editor) **or** let the app propose it: when a match is plausible but not
   certain, the candidate goes to **Auto** instead of touching your text.
3. **Accept a candidate** in the window (*Add as alias*): it becomes an Auto entry, **not** one of
   your own words. *Ignore* drops it. *→ mine* promotes an accepted entry into your dictionary when
   you decide it belongs there. *Clear auto* empties the store.
4. **It applies from the next dictation** — both files are re-read whenever they change, so there is
   no restart and no reload button.
5. **Wrong or obsolete?** Set `enabled = false`, delete the row, or press the tray's
   *Undo last correction* to re-paste a single utterance as the model heard it.

`parakeet-cage --pending` lists Auto's candidates in a terminal:

```
heard "castle" -> "kestrel"  (phonetic, distance 1, seen 3x)
```

## 3. Formats

```toml
# lexicon.toml - yours; comments, spacing and ordering are preserved
schema_version = 1

[[word]]
word = "kestrel"                  # what gets typed
aliases = ["castrell", "kestral"] # spellings the model produces instead
enabled = true                    # false switches just this entry off
hits = 0                          # maintained by the app, rewritten in place
```

```toml
# auto.toml - the app's proposals; managed through the window
schema_version = 1

[[candidate]]                     # heard but never applied, awaiting your decision
heard = "castle"
suggested = "kestrel"
method = "phonetic"
distance = 1
count = 3

[[word]]                          # accepted from a candidate
word = "kestrel"
aliases = ["castle"]
enabled = true
hits = 2
```

- `word` is required; the rest may be omitted.
- Matching is case-insensitive and whole-word only. Multi-word entries (`word = "Parakeet Cage"`)
  match as phrases.
- Your file is safe to hand-edit and to version: the app only rewrites `hits = N` values, in place.
  `auto.toml` is regenerated by the app when it changes, so keep notes about it in your own file.
- Both are plain text: copy them, back them up, keep them in your dotfiles.

## 4. What the app will not do

- It cannot change what the model *hears* — the Parakeet TDT runtime rejects decoder hints — only
  what gets pasted.
- It never writes an entry you did not type into your dictionary; proposals stay in Auto, and only
  *→ mine* moves one across.
- It never queues a candidate that is not a near-miss of a word already in one of the stores:
  discovering brand-new vocabulary from your transcripts is not implemented.
- It never rewrites a well-known word on a guess: a match must be exact, or — for rare words — share
  an identical consonant skeleton. Anything looser becomes a candidate.
- It never interrupts dictation to ask: corrections are announced by log lines and the tray's
  *Undo last correction*, and nothing else.
